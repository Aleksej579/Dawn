# Dawn — заметки для Claude

## Общение и процесс
- Общение на русском, кратко. Комментарии в коде — только на английском.
- Сначала анализ, правки — после согласования. Пользователь ведёт по пунктам: он называет тему, я анализирую, решаем «правим / пропускаем».
- «делай» / «исправь все» = выполнить весь согласованный список, не сужать до «рекомендованных» и не переспрашивать.
- Не редактировать `assets/*.out.css` / `assets/*.out.js` — это результат сборки.

## Сборка и запуск
- `npm start` = `shopify theme dev` + `gulp` (watch).
- `dev/scss/**/*.scss` → `assets/*.out.css` (sass + autoprefixer), `dev/js/*.js` → `assets/*.out.js` (babel + uglify).
- Суффикс `.out` в `dev/` — конвенция проекта, это исходники.

## Секция `0-name` — главное
Файлы: `sections/0-name.liquid`, `dev/scss/sections/0-name.out.scss`, `dev/js/0-name.out.js`.

**Что это:** личный конструктор-заготовка разработчика, НЕ готовая секция. Собраны лучшие практики и базовые паттерны (баннер, слайдер, сетка карточек, аккордеон, табы, карточки блока/товара/статьи, медиа с fallback). На `templates/index.json` стоит только как тестовый стенд.

**Как используется:** три файла копируются в проект → лишнее удаляется во всех трёх → нужное дорабатывается под дизайн → переименование: `name`/`__` → короткий префикс секции (banner-main → `bm__title`), `name-section` → `bm-section`, `data-name-*` → `data-bm-*`, `NameSection` → `BmSection`, схема (`name`, `class`, `presets`). Чек-листы переименования — в комментариях в начале `.liquid` и `.js`.

**Цели и приоритеты:**
- Современно и «по науке», но без перегруза: читаемость и простота важнее полноты.
- 70–80% проектов — Dawn, остальные — другие темы, часто без сборки → максимальная переносимость, минимум зависимостей. SCSS должен работать как обычный CSS (только нативная вложенность, без `$`, миксинов, `//`-комментариев). JS — обычный браузерный, без `import`.
- Секция сама подключает свои зависимости (GSAP подключён в `.liquid` секции, не в `theme.liquid`).
- Минимум обёрток и классов: если элемент достижим вложенным селектором от родителя с классом (`ul li`), отдельный класс не нужен.
- Настройка в основном через код, кастомайзеру тоже уделяется внимание.

**Это НЕ баги (намеренно):**
- Один тип блока `base_block` выводится сразу в нескольких вариантах (слайдер, сетка, аккордеон) — при адаптации оставляют нужный.
- title/subtitle/кнопка и в `<header>`, и в оверлее баннера — альтернативы (header как rich text / баннер с оверлеем).
- Закомментированные варианты (фон секции `--section-bg-*`, `page-width` на `__container` для full-bleed фона, альтернативные стили стрелок).
- `base_block` — нейтральное имя-заготовка, переименовывается после выбора типа секции.

## Архитектура `0-name`
**Liquid**
- Корень — custom element `<name-section>` (без JS → `<div>`). Отступы — CSS-переменные `--section-*` в `style`, логика в SCSS.
- `content_blocks = section.blocks | where: 'type', 'base_block'` — для слайдера/сетки/аккордеона; `@app`-блоки выводятся отдельным циклом.
- Медиа в карточке: видео → картинка → плейсхолдер; постер видео = картинка, иначе `video.preview_image`.
- Кнопка без URL: `role="link" aria-disabled="true"` вместо `href` (как в Dawn).
- Заголовок richtext: `replace: '</p><p>', '<br>' | remove: '<p>' | remove: '</p>'` (переносы и `<em>/<strong>` нужны клиентам).
- Картинки через `image_tag` с `widths`/`sizes`; баннер первой секции — `fetchpriority: high`.
- Настройки: `slider_columns` (шаг 0.1, дробные — ок) и `grid_columns` (шаг 1).

**SCSS (компонентный подход)**
- Слой 1: вложенная раскладка под `.name__wrapper` (контекст).
- Слой 2: базовые компоненты на уровне `.name` — `article` (карточка), `.__media--wrapp` (обёртка задаёт размер, медиа на 100%), `a.__link`, пресеты Swiper. Обёрнуты в `:where()` — самые слабые правила, контекст перебивает их вложенностью.
- Сетка: `minmax(0, 1fr)`; в сетке медиа заполняет ячейку (мозаика `col_span`/`row_span`), в слайдере — `aspect-ratio: 4/3`.
- Слайды: `box-sizing: border-box` (Swiper ставит content-box, Dawn наследует).

**JS**
- Custom element с защитой `customElements.get`. CORE (`connectedCallback`/`disconnectedCallback`/`init`) + независимые модули.
- Все слушатели и очистка — через один `AbortController`. Удалить модуль = вызов в `init()` + его блок.
- Хуки для JS — `data-name-*`, классы — только для стилей.
- Корзина: форма `{% form 'product' %}`, один запрос `/cart/add.js` с `sections`, отрисовка через Dawn `cart-drawer.renderContents`; без drawer форма отправляется нативно.

## Открытые вопросы
- Swiper v10 грузится глобально в `layout/theme.liquid`; ~6 старых секций на него рассчитывают, другие подключают свои версии (v8/v9/v11). Наведение порядка — отдельная задача.
- Старые `sections/0-*.liquid` — разовые секции из прошлых проектов; `0-name` заменяет необходимость в их библиотеке.
